Converged design decisions (2026-06-03) for the Live Preview rendering rework, after the float/wrap feasibility probes (see [[lp-float-wrap-feasibility]] for CDP proof). All keep **native editing (markdown-first)** and **R0**. Now folded into the canonical docs: `architecture.md` AD5/AB9/AB16/AB20, `implementation-plan.md` §2.4/§3.3, `test-plan.md` §3/§4, and the resolved entries in `issues.md` (the standalone `lp-rendering-rework-plan.md` was deleted once its content landed in those artifacts).

**IMPLEMENTED (2026-06-04)** — all 6 slices landed on `main` (commits fa512d8 writer, 99f1527 normalization, fcdd897 inline render, d899a8e tall-float, 8c163a0 bare-embed, + a docs commit), each CDP-verified in the examples vault. Realization notes / deviations from the decisions below:
- **D1 inline non-BFC float:** shipped (new `"standalone"` WidgetMode, `block:true` retired from the main path; `.lie-wrapper-standalone` has `z-index:1`). CDP: 0 height desync over 35 lines, 0 click-steal, multi-line wrap beside the float, image clickable.
- **D2 normalization:** a CM `updateListener` appends `{.lie-img}` to bare embeds, gated on a non-`lie.*` userEvent (so it never fires on file-open or on our own writes), debounced + self-terminating; + "Normalize images (note/vault)" commands; + the serializer **always emits the marker** (so reset never strips back to bare). Setting `autoNormalizeImages` (default on). ALL plugin writes funnel through ONE shared `isolateHistory.of("full")` writer (`src/source-writer.ts`, Slice 1) → exactly one undo step per edit (CDP-proven). `@codemirror/commands` stays an esbuild external; a minimal ambient decl in `env.d.ts` gives tsc `isolateHistory`.
- **D3 bare-embed fallback:** realized as **CSS, not the planned imperative JS fake-link** — the native-image suppression is scoped to `.cm-line` embeds, so a block-promoted bare embed simply shows Obsidian's OWN native block image (CDP: 351px, was a blank 6px). Cleaner, same goal, strictly isolated; erodes via normalization (CDP: editing a bare image makes it a `{…}` widget). Root cause of the old blank: our `> .image-wrapper { display:none }` hid the wrapper holding the img.
- **D5 tall-float cap:** the shared `applyTransformToImage` marks a tall float `.lie-tall` (declarative height estimate, no DOM measure, AD6); `body.lie-safe-tall-float` (the `tallFloatSafe` setting, default safe) stacks it as a block in BOTH views via `…:has(img.lie-tall){float:none}`. Imperfect for width-only portrait floats (estimate assumes landscape) — accepted (the glitch is harmless).
- **Reveal regression found & fixed in CDP (Slice 3):** the inline widget nests the active line's revealed source tokens, so the old `:has(> .cm-formatting)` no longer fired and the fake link DOUBLED the native source while editing. Fixed by keying the fake's hide on `.cm-active` (robust to nesting). Auto mode now reveals the source on cm-line **hover** (pure CSS — the image + source share the line, so no JS bridge; the `.lie-peek` regression-hack is obsolete).

**SUPERSEDED by the A/B'/C follow-up (2026-06-04)** — D2 and D3 above are now obsolete; the model got simpler:
- **A (cca476e):** the native image is killed UNIFORMLY (suppression unscoped: `.cm-content .internal-embed.image-embed > img, > .image-wrapper`), and OUR widget renders in EVERY case — inline for a `{…}` embed, **`block:true`** for a bare one (lands as a `.cm-content` child next to the image-suppressed native embed). This makes the D3 "show the native block embed" bare-fallback OBSOLETE: the native image is never visible.
- **B' (4053f95):** the auto-normalization (D2) was REMOVED entirely — no CM `updateListener`, no `autoNormalizeImages` setting, no "Normalize images" bulk commands. It was no longer load-bearing (A renders bare embeds fine) and it caused an undo loop; removing it killed the loop. `{…}` is now written ONLY by a real plugin action (transform/class via the toolbar), still via the shared isolateHistory writer.
- **C (aff1847):** the `.lie-img` marker was dropped — `renderer.ts` no longer adds it to the img, `serializeTransform` no longer emits it (empty transform → ""); our images are identified by the `.lie-image-area` box parent / `.lie-inline`. `parseAltText` still SKIPS a `.lie-img` token, so old `{.lie-img …}` notes keep parsing.
- Net: native image suppressed uniformly; our widget always renders (inline `{…}` / block bare); no normalization, no marker; the fake-link lives in the cm-line (the `{…}` case). The Reading-view sizing cluster is a separate pure-CSS follow-up.

**1. Render images as INLINE widgets in their OWN non-BFC cm-line** (not the current `block:true` overlay). The host `.cm-line` stays non-BFC, so a `float:left/right` ESCAPES into `.cm-content`'s BFC and wraps the following sibling cm-lines. Wins at once: no block-widget height desync, no `contain:paint` clipping, the **fake-link gets a uniform home** in the populated cm-line, and **lie-left/right wraps multi-line in LP**. CDP-verified.

**2. Source normalization → every image carries `{…}`.** Obsidian block-promotes a bare `![](url)` line (no `{…}`) into its own `.cm-content` child with NO cm-line, which swallows our inline widget. Fix: ensure every embed has a `{…}`. **Lazy on insert/edit (always on)** + a **command/setting for existing content (bulk)**. NOT on file-open (avoids mass-dirtying / sync churn). Portability is fine — `{.class …}` is recognised Pandoc/kramdown attribute-list syntax.

**3. Bare-embed JS fallback** (scoped safety net) for the transient un-normalized case: insert the fake-link imperatively. Accepts slightly-delayed / less-native; kept STRICTLY isolated from the declarative path; only fires when `{…}` is absent. Erodes to ~never as normalization runs.

**4. Float in LP is BACK** — supersedes the old "Option A: reading-view-only float". Add `z-index:1` to the float wrapper so the image stays clickable (hover-toolbar/select); CDP-verified, no collateral (wrap text still editable, fake-link/source still hittable).

**5. Tall-float cap (DECIDED).** A float taller than CM6's ~250px above-viewport render margin (`VP.MaxCoverMargin`, inlined const in `@codemirror/view` — not configurable; CM6 is an esbuild external = Obsidian's own bundle) derenders prematurely when scrolling DOWN past it (wrap dissolves; **no desync — harmless**; only the top-exit direction, since the anchor is at the image top). Decision: **above the threshold, fall back to non-floated block rendering**, exposed as a **settings toggle (default = safe fallback)** which doubles as the place to explain the limitation. **The toggle governs LP AND reader identically** (for cross-view consistency / R0): safe = non-float block in both; permissive = float-wrap in both (accepting the LP-only disappear glitch). Note: the ~250px threshold is an LP/CM6 artifact (reader has no such limit), applied to reader purely to keep a given image's appearance consistent across views — a deliberate "consistency over capability" choice for tall images.

Why the whole rework is safe: **float in LP is fully broken today**, so nothing that currently works regresses — this strictly improves a broken feature.
